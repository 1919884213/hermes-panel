# session-token-detail · 会话 Token 详情 / 费用估算

Hermes 桌面端（Electron）状态栏插件。右下角一枚常驻 chip 显示**当前聚焦会话**的上下文占用
与花费，点开是明细面板。

```
[◧ 23%  45.2k/200k  · ¥0.680]        ← chip：上下文占比 · 已用/上限 · 本会话花费
```

- 花费是**按你自己填的单价估算**的，不是后端账单（面板里与后端上报的 `cost_usd` 并列显示）
- 数据两路取：`host.state.focusedUsage`（后端每 2~3 秒推的实时快照）+ 打开面板时补一次
  `session.usage` / `session.context_breakdown` 权威 RPC。缺一路也照常显示

## 安装

```bash
cp -r session-token-detail "<HERMES_HOME>/desktop-plugins/"
```

Windows 默认 `D:\APP\hermes\desktop-plugins\`，Linux/macOS 是 `~/.hermes/desktop-plugins/`。
目录名**必须**是 `session-token-detail`。装完 `Ctrl/⌘K` → **Reload desktop plugins** 生效；
之后改文件会自动热重载（保存即加载）。

桌面插件**不需要**写进 `config.yaml` 的 `plugins:` 段（那是 CLI 插件系统）。

## 面板里有什么

| 区块 | 内容 |
|---|---|
| 上下文窗口 | 已用 / 上限 · 百分比 + 分段进度条（按类着色）+ 数据来源（实测 / 估算） |
| 会话费用 | 合计 + 五条分项算式（输入 / 输出 / 缓存命中读 / 缓存写入 / 每次调用），推算出来的行标 `≈` |
| 用量与性能 | 输入 / 输出 / 推理 / 缓存命中率 / 吞吐 t/s / 平均延迟 / 合计 / API 调用 / 上下文压缩（3×3 网格） |
| 上下文构成 | 按类拆分（系统提示 / 工具 / 技能 / 记忆 / 对话…）。**默认收起** —— 进度条已给了大概比例 |
| 价格配置 | 价格配置文件列表（≤20）：单选激活、行内改名、删除；「新建配置（复制当前价）」；「此会话独立用」下拉 |
| 价格设置 | 单价输入（当前生效的那一套）+ 分档条 + 「取网关价目 / 设为默认价 / 清空手填价」+ 美元细节（网关原价与汇率） |

右上角两个按钮：**复制成纯文本**（一份带分项与档位的快照）、**手动刷新**。

> 面板高度是刻意压过的：九个指标排成 3×3 网格、「上下文构成」与「价格设置」默认收起。
> 要改信息密度就动这两处的默认值。

## 价格怎么算

五个字段，**每百万 tokens** 计价（`每次调用` 例外，那是每次 API 调用的固定费）：

```
费用 = 输入(缓存未命中) × 输入价 + 输出 × 输出价
     + 缓存读 × 缓存读价 + 缓存写 × 缓存写价 + 调用次数 × 每次调用价
```

口径与 Hermes 自己的 `agent/usage_pricing.py`（`CanonicalUsage` / `PricingEntry`）一致：
`prompt_tokens = input + cache_read + cache_write`，其中 `input` 是**缓存未命中**的那部分。

⚠️ 后端 usage 只带一个四舍五入过的 `cache_hit_pct`，拿不到 cache_read/write 的原始计数，
所以**缓存读按命中率推算、缓存写取残差** —— 这两行在面板里标 `≈`。要算得准，这两项单价
也要填（DeepSeek 之类没有缓存写入费的填 0 即可）。

### 价格来源（四层，优先级从高到低）

1. **价格配置文件** —— 你自己建的那几套价，可命名、可切换、可给单个会话独立绑定
2. **手填** —— 按模型保存的五个数
3. **网关价目** —— 从 `model.options` RPC 自动取回（$/Mtok，按汇率折算），本地缓存 24h
4. **通用默认价** —— 连网关都不认识的模型（自建 vLLM、自定义 endpoint）的兜底

换模型不用重新填价，就是靠第 3 层。四层全空时面板提示「还没填价格」，**不会**显示一个
0 元假账单。

## 价格配置文件

- 最多 20 套；每套可改名、可改价；点单选点切「全局激活」，被会话独立绑定的会话不受影响
- **新建 = 复制当前生效的那套价 + 立即切到它**：新配置当场成为「正在生效」的那一个，
  下面几个价格框接着改的就是它（跟随全局的会话 → 设成全局激活；已独立绑定的会话 →
  绑定改指新配置）。两套价内容一样，所以切换这一步不会改变任何花费
- 删除配置时，指向它的会话绑定与激活指针一并清干净，不留悬空引用（会退回跟随全局）
- v1 老落盘（只有 `currency` + `byModel`）升级时被收编成一个叫「默认配置」的配置，
  **不自动激活** —— 免得把老用户「按模型手填」的行为静默改成「所有模型都套这套价」

## 上下文分档（价目表按输入大小分价时用）

有些模型按**输入大小**给两套价（价目表写成 `输入 [0, 272K)` 与 `[272K, +∞)`）。在这种
配置里点「加一档」，就得到一个两档的价格配置文件：

- **自动**：按当前上下文占用（`context_used` —— ≈ 下一次请求的输入大小）自动切档，
  价格随阈值变化。区间左闭右开：`271999 → 第 1 档`，`272000 → 第 2 档`
- **点某一档**：手动锁定为它，不随上下文变化；点回「自动」复位
- 上下文未知（还没上报）时按第一档算，面板会写明
- 「删掉这一档」删到只剩一档就退回不分档；「输入上限」可改（不许越过上一档，最后一档是无上限）
- **分档只挂在价格配置上**（手填 / 网关价 / 通用默认价都是单档）

不变式：**价格框改的永远是「正在生效的那一档」**，其余档一动不动；面板顶部的
`价格来源：配置文件「xxx」 · 档 1/2` 与框里的数、以及计费口径三者始终指向同一处。

## 落盘

存在插件自己的 `ctx.storage`（渲染进程 localStorage 命名空间
`hermes.plugin.session-token-detail.*`，键 `prices`）：

```jsonc
{
  "currency": "CNY",          // 显示货币（¥/$）
  "rate": 7.2,                // 网关 $/Mtok → ¥ 的折算汇率
  "activeProfile": "p1",      // 全局激活的配置文件
  "profiles": {
    "p1": {
      "id": "p1", "name": "官方价",
      "prices": { "input": 0.08, "output": 0.4, "cacheRead": 0.008, "cacheWrite": 0.1, "request": 0 },
      "tiers": [                                   // 可选：满 2 档才算分档，单档就不写这个键
        { "maxContext": 272000, "prices": { /* … */ } },
        { "maxContext": null,   "prices": { /* … */ } }   // 最后一档无上限
      ],
      "tierLock": -1            // -1 = 自动选档；否则锁定的档位下标
    }
  },
  "sessions": { "20261001_…": "p1" },   // 会话 → 配置文件的独立绑定
  "byModel": { "deepseek-chat": { /* 五个数 */ } },
  "gateway": { "glm-4.6": { "at": 1759…, "prices": { /* … */ }, "provider": "zhipu" } },
  "defaults": { /* 通用兜底价 */ }
}
```

读进来的每一份都过 `parseStoredPrices`：坏字段、悬空绑定（指向已删配置）、坏档位一律丢掉。
分档时 `prices` 是**第一档的镜像**，好让只认 `prices` 的老读取路径不看到过期数据。

## 开发与测试

```bash
cp -r "<HERMES_HOME>/desktop-plugins/session-token-detail/node_modules" ./   # 只有测试台需要
node tests/test.mjs        # 退出码非 0 = 有 FAIL，最后一行是 "N passed, M failed"
```

离线测试台桩掉 `@hermes/plugin-sdk`，用真 React + `react-dom/server` 静态渲染**真正的
`plugin.js`**，然后按文字点按钮、按字段敲输入框驱动**真实处理器**（不是重写一遍逻辑）。
覆盖范围、桩的取舍、以及「怎么从外面回读插件的落盘」见 [`tests/README.md`](tests/README.md)。

写这个插件的硬约束（加载器直接拒）：只能 `import` `react` / `react/jsx-runtime` /
`@hermes/plugin-sdk`；文件不编译，只能写 `jsx(type, props, key)`，不能写 JSX 语法；
i18n 每个 key 必须在 zh / en 两套 bundle 里都有且不留死 key。

## 已知限制

- 花费是**估算**：缓存读/写是按命中率推算的（标 `≈`），多模态、工具计费等杂项单价无法
  表达（价目表里的「其他费用」这类列只能忽略或折算进某一项）
- 分档按「当前上下文占用」选档，等于把「下一次请求的输入大小」当输入量 —— 与按单次
  请求真实输入计费的口径可能有偏差（会话累计 `prompt` 会一路涨过阈值，不适合当选档依据）
- 单价是**按配置存**的，不是按模型：同一套价换模型不用重填，但不同模型要分别建配置
  （或用「按模型手填」那一层）
- 界面只用 SDK 的主题化组件（含 `Select`）；原生 `<select>` 在深色面板里是白底、展开一片白，
  别退回去用
